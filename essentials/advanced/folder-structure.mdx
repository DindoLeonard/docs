## The tree


## What the table shows

- **The middle column is just the first column without `.mdx`.** That is the
  entire path rule.
- **The third column is the middle column with a leading slash.** Folders become
  URL segments; nothing else does.
- **`index.mdx` is the exception**, mapping to `/` rather than `/index`. The same
  applies inside a folder: `guides/index.mdx` would serve `/guides`.
- **Column four is unrelated to columns two and three.** "Guides", "Essentials",
  and "Advanced" are labels in `docs.json`. Rename any of them and no URL moves.
- **Two rows have no navigation entry** and behave completely differently from
  each other: one is a working page with no sidebar link, the other has no URL
  at all.

## Conventions worth copying

Mintlify enforces almost none of this — a flat folder of 200 `.mdx` files would
build fine. These are the habits that keep a growing site manageable:

<Steps>
  <Step title="One folder per tab, named after it">
    The "API reference" tab keeps its pages in `api-reference/`. Since tab names
    are invisible to URLs, the folder is what makes `/api-reference/...` happen.
  </Step>
  <Step title="Let folders mirror groups, one level down">
    `essentials/advanced/` matches the nested "Advanced" group. Someone reading
    the sidebar can guess the file path, and the other way around.
  </Step>
  <Step title="Keep shared content in /snippets/">
    Files there never become pages, so the folder stays unambiguous.
  </Step>
  <Step title="Put images in /images/ and reference them from the root">
    This project has no images yet, but `/images/diagram.png` in an `.mdx` file
    resolves from the project root, the same way `/logo/light.svg` does in
    `docs.json`.
  </Step>
</Steps>
